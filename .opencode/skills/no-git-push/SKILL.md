# Правило: Git операции только с разрешения пользователя

## Что запрещено без явного разрешения

- `git commit` — любой коммит
- `git push` — любой пуш
- `git merge` — слияние веток (если не попросили)
- `git rebase` — переписывание истории
- `git reset --hard` — сброс
- `git checkout -b` / `git branch -D` — создание/удаление веток (если не попросили)
- `git remote add/remove` — изменение удалённых репозиториев
- `gh pr create` / `gh repo` — GitHub операции
- Любая команда с `--force` флагом

## Что разрешено без разрешения

- `git status` — просмотр состояния
- `git diff` / `git log` — просмотр истории и изменений
- `git fetch` — получение данных (не изменяет локальные файлы)
- `git branch` (просмотр) — список веток
- `git stash list` — просмотр стэша

## Правильный флоу

1. Пользователь просит изменить код → я изменяю
2. Я показываю `git status` + `git diff --stat` (что готово к коммиту)
3. **Жду явного разрешения**: «коммить», «пушь», «заливай», «закоммить это»
4. Только после этого выполняю commit/push
5. Коммит-месседж согласовываю с пользователем (или предлагаю вариант)

## Если пользователь не дал разрешения

- Показываю статус и предлагаю: «Готово к коммиту. Коммитить?»
- НЕ коммичу «заодно» или «автоматически»
- НЕ пушу даже если «это же очевидно нужно»
- Если пользователь молчит — не коммичу

## Исключение

Единственный случай когда можно коммитить без явного разрешения —
если пользователь в начале сессии сказал «коммить всё автоматически»
или аналогичное явное blanket-разрешение.
